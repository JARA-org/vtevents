# Verified public event/deadline endpoints

Inspected September 19, 2026 (America/New_York) using public HTML, linked calendar exports and official pages. This is implementation evidence, not a claim of full calendar coverage or a supported vendor API. Athletics, Discord and the general GobblerConnect adapter are handled separately. Every inventory family below has a concrete seed or an explicit availability limitation.

## Concrete payload checks

### University events

[The Hokie Pivot detail](https://events.vt.edu/events/2026/09/2026-09-the-hokie-pivot.html) returned HTTP 200 and Event JSON-LD with `startDate=2026-09-22T18:30:00.000-04:00`, matching end offset, `EventScheduled`, Place + PostalAddress and Offer price/currency/link. The JSON-LD did not contain an image; preserve a scoped page hero/OG image when available. Keep ticket/registration links distinct from online attendance. Response included ETag and Last-Modified, so conditional requests are supported by the observed response headers. Do not treat HTML rebuild time as source event update time.

### Libraries

[Sample detail](https://calendar.lib.vt.edu/event/17491201) contains Event JSON-LD, including an image on `d68g328n4ug0e.cloudfront.net`, offline attendance, organizer and campus venue. Its [advertised ICS export](https://calendar.lib.vt.edu/event/17491201/ical) returned `text/calendar` with UID `LibCal-17491201`, UTC start/end and fuller description. The example is a scheduled therapy-dog activity; this does not justify importing ordinary office opening hours. Export DTSTAMP is not proof of a substantive content change. The homepage had no ETag/Last-Modified in the observed response: canonical content hashing is necessary.

### Career

[Data Science Connections detail](https://career.vt.edu/events/2026/09/22/data-science-connections-career-fair-fall-2026/) has no Event JSON-LD but directly advertises [its ICS export](https://career.vt.edu/events/2026/09/22/data-science-connections-career-fair-fall-2026.ics/). The export returned `text/calendar`, a stable uConnect UID, `DTSTART:20260922T140000Z`, `DTEND:20260922T200000Z`, location, URL and summary. DTSTAMP reflected export generation, so exclude it from semantic revision hashing. The obsolete-looking `/events.html` returned 429 through research retrieval; use the observed current `/events/` navigation instead.

### Registrar and Bursar

Registrar tables are inside `main#vt_main`, each immediately preceded by an h2/h3 term heading. Header cells themselves contain h4 elements; do not mistake those for new term headings. Winter 2026–2027 spans two years, and Spring 2027 includes registration steps in late 2026. Explicit row years take precedence; academic-term context must handle cross-year dates. The page states closing deadlines are 11:59 p.m. unless otherwise specified. A row can combine a nonqualifying term boundary with a qualifying action cutoff, so retain the action clause. Blank/TBD dates do not publish. Bursar's separate table explicitly lists Winter Session 2026 payment on December 10, 2026 and Spring 2027 on January 11, 2027; preserve term and date-only precision.

### Arts and prose sources

[Isidore String Quartet](https://artscenter.vt.edu/performances/isidore-string-quartet.html) demonstrates the critical date trap: metadata/page publication date is June 10, 2021, while the performance is September 25, 2026 at 7:30 p.m. The first main-content paragraphs identify date, theatre, approximate duration and ticket categories. OG supplies a performance image. Related school matinee and post-show discussion are distinct activities; do not flatten every date into the main event.

[Research NSPIRE detail](https://www.research.vt.edu/events/nspire-sept-26.html) explicitly supplies a September 21, 2026 online-only program with multiple sessions. Keep parent program and child sessions distinct if extracting both. [Cranwell calendar](https://international.vt.edu/calendar.html) includes physical, online and mixed entries grouped under Fall 2026 and Spring 2027. Holiday lines and entries with unknown dates must not qualify merely because they share the same calendar.

## Fetch and reconciliation implications

### Implemented adapter verification

The Dining department export at `https://gobblerconnect.vt.edu/ical/virginiatech/ical_club_35584.ics` returned 28 records in the implementation smoke check. It retains upstream GobblerConnect UIDs for reconciliation. Research publishes a Google visualization sheet; the adapter pins its exact public URL, parses the JSON response without executing JavaScript, and discovers only approved research detail URLs. A bounded 20-page research check returned four qualifying events with no request/parser errors and additional pages still pending. Eight-page Arts and Career checks returned two and one events respectively. These counts are observations, not completeness guarantees.

Validation: 91 automated tests passed, along with architecture, historical contract compatibility, frontend/backend type checks and the production build. Live checks used isolated in-memory checkpoints and did not write the application database or invoke AI. Graduate and undergraduate research access and ambiguous financial-aid years remain gaps. Production deployment and remote ANS provisioning were not performed.

- Persist ETag/Last-Modified per final approved URL; send conditional requests. A 304 preserves prior parsed contributions. Headers are hints, not proof that provider records changed.
- No observed universal provider `updatedSince` API exists for these sources. Poll bounded indexes to discover new URLs and conditionally revalidate known live detail URLs. Revalidating only changed indexes misses standalone detail edits.
- Hash normalized event/deadline fields independently from menus, footers, generated timestamps, export DTSTAMP and HTML rebuild metadata. Run semantic extraction only when relevant source content changes, retaining the extraction-version fingerprint.
- Archive pages, pagination limits, request errors, parser failures and robots restrictions mean partial coverage, never an authoritative empty snapshot. Do not withdraw all events after a partial scan.
- Preserve source URL/native ID, event images/alt text, organizer, physical and online venues separately, schedule precision, admission/registration links, prices, audiences, statuses, provenance and explicit update times. Do not indiscriminately collect tracking scripts, credentials, private contact records or unrelated page text.
- Exact upstream IDs or explicit event links establish stronger identity than titles. Dining/recreation departmental Gobbler views should reconcile with their existing upstream records. Contradictory times/places remain visible conflicts; ANS identity does not make a claim true.
- Structured JSON-LD, ICS and known tables need no model. Prose interpretation can use the constrained backend extraction service with bounded inputs and evidence validation. The above audit does not provision a remote ANS identity or authorize arbitrary agents.
- Check robots/terms and respect backoff before enabling production polling. A successful research request does not by itself demonstrate blanket scraping permission. Never bypass private pages, access checks or rate limits.
